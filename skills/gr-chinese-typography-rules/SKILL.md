# 中文排版规则

适用于简体中文语境。**只修改排版，不改变内容含义；受保护内容原样保留。**

下文是本技能的默认编辑风格，不代表所有出版规范。检查时区分格式错误、风格建议和语义疑点；原文已有的合法风格及用户指定的规范优先。

---

## 一、保护边界

### 1.1 绝对不动（逐字符保留）

- 代码块与行内代码的**内部**
- URL、文件路径、shell 命令、环境变量
- JSON / YAML / TOML、正则表达式、配置片段
- Markdown 链接目标 `(...)`、Obsidian `[[wikilink]]` 的目标、图片路径、HTML 标签与属性值；有别名时只检查可见别名
- 数学公式与 LaTeX（`$...$`、`$$...$$`、独立公式行）
- 股票代码、产品型号、版本号、标识符、API 名与字段名
- 引述的原话、法条、公告、他人稿件的原文片段
- 用户明确说明要保留的写法

### 1.2 绝对不改

事实、数字、单位换算、语义、语气、句子结构、观点、段落顺序、标题层级结构、段首缩进、链接与正文间距。

**专有名词：不猜测、不改写不熟悉的拼写。** 只有在能确认官方写法（3.7）时，才可以只修正大小写（`github` → `GitHub`），不改变字母本身的拼法；拿不准官方写法就原样保留，不要猜。

句子长度、被动语态、段落组织等表达层面的规则属 `gr-content-ai-avoid`，需要时可配合使用，不是本 Skill 的依赖。

自检时逐项看 diff：受保护片段逐字符一致；数值、正负号、小数点、单位、日期含义、链接目标和 Markdown 结构不变。全角数字转半角等归一化必须保持同值；品牌大小写修正只限普通正文，标识符不动。不能靠「删掉标点和空格后相同」判断安全，因为这会漏掉负号、小数点等含义变化。

### 1.3 上下文优先级（规则冲突时按此裁决）

按以下顺序裁决，前项优先：

1. **保护边界** → 1.1 的内容原样保留
2. **用户或发布平台明确指定的风格** → 覆盖普通正文的默认值
3. **原文已有的合法且一致的写法** → 不为了个人偏好改动
4. **语境默认值** → 完整英文句、英文书名及英文专名内部按英文规则；中文正文按下文规则

## 二、两种工作模式

| 用户说 | 模式 | 输出 |
| --- | --- | --- |
| 检查、看看有没有问题、诊断、审一遍、发布前排查 | **检查模式** | 问题清单，不重写全文 |
| 统一、修正、规范化、排版、润色格式、按规范改 | **修正模式** | 修改后的完整文本 |
| 意图不明，且无法从上下文判断 | 按**检查模式**处理 | 只列问题和建议，不推定已有修改授权 |

**检查模式**输出逐条列出，每条包含：位置（行号或上下文片段）、原文、建议改法、依据的规则编号。不确定的（引号风格、单位空格、专有名词写法）标为「候选」，交给用户判断，不擅自算成错误。

**修正模式**只做最小排版修正：改确定性错误，保持原文已有的合法风格选择。文本请求返回修正版；文件请求修改指定文件并简述变化。用户只要正文时不附说明。

## 三、核心规则

### 3.1 空格

**中文与英文之间加空格。**

- 正确：在 LeanCloud 上，数据存储围绕 `AVObject` 进行。
- 错误：在LeanCloud上，数据存储围绕`AVObject`进行。

**中文与阿拉伯数字之间加空格。**

- 正确：今天买菜花了 5000 元。
- 错误：今天买菜花了5000元。

**并列含义相对的中文之间用半角 `/`，前后加空格。**

- 正确：登录 / 注销、读 / 写、输入 / 输出
- 例外：前后已是自带空格的专有名词或全角标点时不加。

**数字与单位之间加空格（唯一定义，其他章节不再重复）。**

- 默认加空格：宽带 10 Gbps、SSD 20 TB、内存 16 GB
- 高频技术单位 `KB / MB / GB / TB / Hz / MHz / GHz` 按平台惯例可紧贴：20TB、3.2GHz
- 正式稿件（研报、公众号、对外文档）倾向加空格；技术文、日常表达可紧贴
- **同一篇内必须一致**，不允许 `20 TB` 和 `20TB` 混用

**不加空格的位置：**

- 数字与 `%`、`‰`、角度 `°`：默认写 `15%`、`33°`。温度单位另看整体：`25 °C` 不属于角度紧贴规则；用户指定的科技排版规范优先
- 全角标点与相邻字符：`刚买了一部 iPhone，好开心！`
- Markdown 格式标记本身不制造空格需求，按可见文字判断：`这是**重点**内容`、`使用 **GitHub** 登录`；不删除语法必需的空格，不改链接与正文间距
- 书名号、引号、括号的内侧：`《Thinking, Fast and Slow》`、`「Stay hungry」`

**专有名词例外：** 官方写法自带特殊格式的按官方原样，如「豆瓣FM」。`iOS`、`macOS`、`iPhone` 本身是专有名词，与中文接壤时仍加空格。

### 3.2 全角与半角

中文语境默认全角标点：`，。；：！？、（）【】《》「」『』——……`

- 正确：嗨！你知道嘛？今天前台说「喵」了哎！
- 错误：嗨! 你知道嘛? 今天前台说 "喵" 了哎!

**完整英文句、英文书名内部保持半角**（1.3 的语境默认值）：

- 正确：乔布斯说「Stay hungry, stay foolish.」
- 正确：推荐《Hackers & Painters: Big Ideas from the Computer Age》
- 错误：乔布斯说「Stay hungry，stay foolish。」

**数字用半角**：`1000 元`，不写 `１０００ 元`。设计稿、海报为对齐可用全角。

**省略号**默认用 `……`（U+2026 连用两次），不用 `。。。`、`...`、单个 `…`。完整英文句内部保持英文写法。若与「等」重复表达列举未尽，只提示冗余；不要在排版修正中删字，也不要把表示迟疑的「等等……」误当列举。

**破折号**用 `——`（两个 U+2014），不用 `--`、`-` 或单个 `—`。

### 3.3 引号

**默认：保持原文已在使用的合法中文引号风格，全文统一。** 只有原文风格混乱、或用户/平台明确要求时才统一到某一种。

以下两种风格均可用，同一层级、同一语境尽量统一；原文引用和完整英文内容不参与强制统一：

- **直角引号（本项目偏好）：** 外层 `「」`（U+300C / U+300D），内层 `『』`（U+300E / U+300F）
  - 示例：「老师，『有条不紊』的『紊』是什么意思？」
- **全角弯引号（传统出版与多数平台默认）：** 外层 `“”`（U+201C / U+201D），内层 `‘’`（U+2018 / U+2019）
  - 示例：“老师，‘有条不紊’的‘紊’是什么意思？”

**中文正文中充当引号的 ASCII U+0022（`"`）和 U+0027（`'`）默认改为中文引号。** 同时检查配对和嵌套；英语所有格、撇号和英寸符号不能当作中文引号替换。

- 检查信号：引号在编辑器里显示为笔直竖线、左右完全对称、不带向内弯折，就是 ASCII 直引号。
- 例外：代码、命令、JSON 内部的 ASCII 引号属于保护内容，不动（1.1）。

### 3.4 括号

- 中文正文用全角括号 `（）`，前后不加空格：核磁共振成像（NMRI）是什么原理？
- 括号内是**完整英文句或英文短语**时，内部按英文规则：RightCapital (a fintech company) 的手机应用（App）于近日发布。
- 被注释对象和括号内容**都是英文**时，用半角括号并在前面加一个空格。
- 括号内是中文语境的并列项，用顿号：（如 React、Vue.js、Angular）
- 数学公式整体受保护，不改其中括号：`收益 = 本金 × (1 + r)`
- 句内括注随所在句结束：详见第 1.3 节（第 26 页）。独立的句外括注可在括号内结束：（数据截至昨日。）不要机械移动句号

### 3.5 标点

**中文句子中并列词语默认用顿号 `、`**，英文并列词同样适用；最后一项已有「和」或「以及」时保留，不为排版新增连接词。分句之间的逗号不能机械替换成顿号。

- 正确：常用库有 pandas、NumPy、Polars 和 DuckDB。
- 错误：常用库有 pandas, NumPy, Polars 和 DuckDB。
- 例外：整句为英文时用半角逗号：`Common libraries include pandas, NumPy, and DuckDB.`

**正式正文默认不堆叠标点。** 允许 `？！` 或 `！？` 单次并用。社交文案中的情绪性重复先作为风格建议，不擅自削弱语气。

- 正确：她竟然对你说「喵」？！
- 错误：德国队竟然赢了巴西队！！！！！

**标题末尾默认不加句号、逗号、顿号、分号、冒号**（`。，、；：`）；问号、叹号、省略号及配对闭合符号可保留。

- 正确：`## 为什么夏普比率会失真？`
- 错误：`## 三个常见的过拟合信号。`

### 3.6 数字区间

- **连接符**：本项目偏好「至」或 en dash `–`（U+2013）；全角浪纹线 `～`（U+FF5E）也是合法风格，原文统一使用时按 1.3 保留。半角 hyphen `-`、半角 `~` 只提示候选，确认是数值区间后再改
  - 推荐或可保留：年化收益 15%–20%、2020-01-01 至 2024-12-31、Q1–Q3、换手率 3–5 倍/年、3～5 天
  - 待检查：15%-20%、3 ~ 5 倍/年
  - 注意：`2024-03-31`、`2024-03` 里的 `-` 是日期格式的一部分；电话号码、ISBN 和其他编号中的连字符也不是区间连接符，不要改
- **百分比区间建议两端明确**：67%–89%。`67–89%` 只提示候选，不在上下文不足时猜补百分号
- **普通单位可以共用**：`3–5 倍/年`、`132–234 kg` 均可；原文写 `132 kg–234 kg` 也可保留。单位换算、负数和跨零区间先核对含义，不机械替换每个连字符

### 3.7 专有名词大小写

按品牌官方写法：GitHub、iPhone、macOS、JavaScript、Microsoft、LeanCloud。
错误：github、GITHUB、Github、gitHub。

上述修正仅适用于正文中的品牌名；代码、URL、用户名、字段名和原文引用不改，不因此修改 HTML / CSS。

### 3.8 日期与时间

没有另行指定风格时，普通中文文本中的日期时间参考以下写法：

- 中文日期：`2024 年 3 月 31 日`（月、日不补零）
- 纯数字日期：`2024-03-31`（补零，ISO 8601）；其中的 `-` 是格式的一部分，不是区间连接符
- 新写正文优先用上述格式；原文 `2024/3/31` 等明确且一致的日期可保留。两位年份或 `03/04/05` 等含义不明时仅提示，不猜测世纪或月日顺序
- 时间用**半角**冒号：`9:05`、`收盘 15:00`；不用全角 `9：05`
- 时间区间用 en dash：`9:30–11:30`

## 四、自检清单

改完或检查完，按顺序过一遍：

1. 中英文、中文与数字之间的空格（最高频错误；Markdown 标记、书名号内侧不加）
2. 全角标点是否用对（`，。；：！？、（）`）
3. 并列是否用顿号（英文并列词也用 `、`）
4. 中文正文里有没有 ASCII 直引号；引号风格是否全文一致
5. 数字与单位的空格是否全文一致
6. 区间连接符与单位含义（百分比建议 `15%–20%`，共用普通单位如 `3–5 kg` 可保留）
7. 标点堆叠、省略号 `……`、破折号 `——`
8. 标题末尾无点号
9. 专有名词大小写
10. 日期、时间格式（中文日期不补零、ISO 日期补零、时间半角冒号）
11. 受保护内容（代码、URL、公式、原文引用）是否被误改

机械项可以跑脚本先扫一遍。脚本在本 skill 目录的 `scripts/` 下，`$SKILL` 指本 skill 的绝对路径：

```bash
python3 "$SKILL/scripts/check_typography.py" 稿子.md
```

脚本只报告，不自动改写。`error` 表示按默认风格可定位的问题，`warn` 表示候选，都需确认语境。`--json` 输出结构化结果；默认退出码为 0，`--fail-on error` 遇 error 返回 1，`--fail-on warn` 遇任一级别问题返回 1；`--level` 只过滤显示，不影响退出码。

默认 `--profile general` 不检查千位分隔符和比较符号空格。处理金融分析、量化研究或数据报告并加载 `financial-notation.md` 时，使用：

```bash
python3 "$SKILL/scripts/check_typography.py" 稿子.md --profile finance
```

两种 profile 都保护常见带标签的电话号码、ISBN、股票代码及六位数字括注等疑似编号；未标记编号仍需人工识别，六位数字括注也可能是普通数值，应人工复核。

引号风格统计以邻接中文字符或中文句读标点作为语境信号，英文段落中的弯引号和所有格不参与统一；原文引用仍需人工确认保护边界。

脚本屏蔽常见代码块、行内代码、链接目标与引用定义、frontmatter、HTML 标签与注释、显式公式和普通引用块。`> [!type]` 开头的 Obsidian callout 按作者正文检查，内部代码、链接目标和嵌套普通引用仍受保护；callout 中若包含他人原话，应标成嵌套引用块或人工保留。列表缩进按内容列判断，嵌套列表和续段仍检查，再缩进四列的代码会屏蔽。未闭合围栏保守屏蔽到文末；普通引用块及 callout 的未带 `>` 续行按块延伸到空行，可能误判相邻正文的归属。它不是完整 Markdown 解析器，不保证识别所有复杂嵌套容器、普通引号中的原话、未标记的配置、文件路径、命令、标识符及全部公式；这些边界需人工确认，最好将待检正文与保护片段分开。无报告不等于全文合规。

已知缩进限制：段落或列表项后未隔空行、相对正文或列表内容列缩进四列及以上的续行，仍可能被误当作代码屏蔽。此类续行和深缩进的子列表需人工检查。
