# 中文排版规则

适用于简体中文语境。**只修改排版，不改变内容含义；受保护内容原样保留。**

---

## 一、保护边界

### 1.1 绝对不动（逐字符保留）

- 代码块与行内代码的**内部**
- URL、文件路径、shell 命令、环境变量
- JSON / YAML / TOML、正则表达式、配置片段
- Markdown 链接目标 `(...)`、图片路径、HTML 标签与属性值
- 数学公式与 LaTeX（`$...$`、`$$...$$`、独立公式行）
- 股票代码、产品型号、版本号、标识符、API 名与字段名
- 引述的原话、法条、公告、他人稿件的原文片段
- 用户明确说明要保留的写法

### 1.2 绝对不改

事实、数字、单位换算、语义、语气、句子结构、观点、段落顺序、标题层级结构、段首缩进、链接与正文间距。

**专有名词：不猜测、不改写不熟悉的拼写。** 只有在能确认官方写法（3.7）时，才可以只修正大小写（`github` → `GitHub`），不改变字母本身的拼法；拿不准官方写法就原样保留，不要猜。

句子长度、被动语态、段落组织等表达层面的规则属 `gr-content-ai-avoid`，需要时可配合使用，不是本 Skill 的依赖。

自检标准：把改动前后的文本都删掉标点和空格，剩下的字符序列应保持一致；本规范明确允许的格式归一化（全角数字改半角、专有名词大小写改正等）不算越界，其余差异就是越界了。

### 1.3 上下文优先级（规则冲突时按此裁决）

1. **代码、公式、机器可读内容** → 原样，不套任何中文排版规则
2. **完整英文句、英文书名、英文专名内部** → 英文规则（半角逗号、句号、省略号）
3. **中文正文** → 中文规则（全角标点、中文引号、中英文间距）
4. **用户或发布平台指定的 house style** → 覆盖第 2、3 条的默认值
5. **全文一致 > 单点最优** → 原文已统一使用某个合法写法时保持它，不为了「更标准」而改

## 二、两种工作模式

| 用户说 | 模式 | 输出 |
| --- | --- | --- |
| 检查、看看有没有问题、诊断、审一遍、发布前排查 | **检查模式** | 问题清单，不重写全文 |
| 统一、修正、规范化、排版、润色格式、按规范改 | **修正模式** | 修改后的完整文本 |
| 说不清楚 | 按**检查模式**处理，并说明改动量 | 清单 + 一句「要我直接改吗」 |

**检查模式**输出逐条列出，每条包含：位置（行号或上下文片段）、原文、建议改法、依据的规则编号。不确定的（引号风格、单位空格、专有名词写法）标为「候选」，交给用户判断，不擅自算成错误。

**修正模式**只做最小排版修正：改确定性错误，保持原文已有的合法风格选择。改完在文末用三五行说明改了哪几类，不逐条罗列。

## 三、核心规则

### 3.1 空格

**中文与英文之间加空格。**

- 正确：在 LeanCloud 上，数据存储围绕 `AVObject` 进行。
- 错误：在LeanCloud上，数据存储围绕`AVObject`进行。

**中文与阿拉伯数字之间加空格。**

- 正确：今天买菜花了 5000 元。
- 错误：今天买菜花了5000元。

**并列含义相对的中文之间用半角 `/`，前后加空格。**

- 正确：登录 / 注销、读 / 写、输入 / 输出
- 例外：前后已是自带空格的专有名词或全角标点时不加。

**数字与单位之间加空格（唯一定义，其他章节不再重复）。**

- 默认加空格：宽带 10 Gbps、SSD 20 TB、内存 16 GB
- 高频技术单位 `KB / MB / GB / TB / Hz / MHz / GHz` 按平台惯例可紧贴：20TB、3.2GHz
- 正式稿件（研报、公众号、对外文档）倾向加空格；技术文、日常表达可紧贴
- **同一篇内必须一致**，不允许 `20 TB` 和 `20TB` 混用

**不加空格的位置：**

- 数字与 `%`、`°`：`15%`、`33°`，不写 `15 %`
- 全角标点与相邻字符：`刚买了一部 iPhone，好开心！`
- Markdown 格式标记与中文：`这是**重点**内容`，不写 `这是 **重点** 内容`
- 书名号、引号、括号的内侧：`《Thinking, Fast and Slow》`、`「Stay hungry」`

**专有名词例外：** 官方写法自带特殊格式的按官方原样，如「豆瓣FM」。`iOS`、`macOS`、`iPhone` 本身是专有名词，与中文接壤时仍加空格。

### 3.2 全角与半角

中文语境默认全角标点：`，。；：！？、（）【】《》「」『』——……`

- 正确：嗨！你知道嘛？今天前台说「喵」了哎！
- 错误：嗨! 你知道嘛? 今天前台说 "喵" 了哎!

**完整英文句、英文书名内部保持半角**（优先级第 2 条）：

- 正确：乔布斯说「Stay hungry, stay foolish.」
- 正确：推荐《Hackers & Painters: Big Ideas from the Computer Age》
- 错误：乔布斯说「Stay hungry，stay foolish。」

**数字用半角**：`1000 元`，不写 `１０００ 元`。设计稿、海报为对齐可用全角。

**省略号**用 `……`（U+2026 连用两次），不用 `。。。`、`...`、单个 `…`。完整英文句内部保留 `...`。省略号不与「等」连用。

**破折号**用 `——`（两个 U+2014），不用 `--`、`-` 或单个 `—`。

### 3.3 引号

**默认：保持原文已在使用的合法中文引号风格，全文统一。** 只有原文风格混乱、或用户/平台明确要求时才统一到某一种。

两种合法风格，任选其一，一篇里只用一种：

- **直角引号（本项目偏好）：** 外层 `「」`（U+300C / U+300D），内层 `『』`（U+300E / U+300F）
  - 示例：「老师，『有条不紊』的『紊』是什么意思？」
- **全角弯引号（传统出版与多数平台默认）：** 外层 `“”`（U+201C / U+201D），内层 `‘’`（U+2018 / U+2019）
  - 示例：“老师，‘有条不紊’的‘紊’是什么意思？”

**唯一必须改的引号问题：中文正文里出现 ASCII 直引号 U+0022（`"`）和 U+0027（`'`）。**

- 检查信号：引号在编辑器里显示为笔直竖线、左右完全对称、不带向内弯折，就是 ASCII 直引号。
- 例外：代码、命令、JSON 内部的 ASCII 引号属于保护内容，不动（1.1）。

### 3.4 括号

- 中文正文用全角括号 `（）`，前后不加空格：核磁共振成像（NMRI）是什么原理？
- 括号内是**完整英文句或英文短语**时，内部按英文规则：RightCapital (a fintech company) 的手机应用（App）于近日发布。
- 被注释对象和括号内容**都是英文**时，用半角括号并在前面加一个空格。
- 括号内是中文语境的并列项，用顿号：（如 React、Vue.js、Angular）
- 数学公式内的括号一律半角（优先级第 1 条）：`收益 = 本金 × (1 + r)`
- 句末括号加注时，句号在括号之外：详见第 1.3 节（第 26 页）。

### 3.5 标点

**并列用顿号 `、`**，英文并列词同样用顿号，最后一项用「和」或「以及」连接。

- 正确：常用库有 pandas、NumPy、Polars 和 DuckDB。
- 错误：常用库有 pandas, NumPy, Polars 和 DuckDB。
- 例外：整句为英文时用半角逗号 —— `Common libraries include pandas, NumPy, and DuckDB.`

**不堆叠标点。** 允许 `？！` 或 `！？` 单次并用，不允许连续重复。

- 正确：她竟然对你说「喵」？！
- 错误：德国队竟然赢了巴西队！！！！！

**标题末尾不加点号**（`。，、；：`）；标号（`？！」》……`）可保留。

- 正确：`## 为什么夏普比率会失真？`
- 错误：`## 三个常见的过拟合信号。`

### 3.6 数字区间

- **连接符**：中文正文用「至」或 en dash `–`（U+2013）；不用半角 hyphen `-`，不用 `~`
  - 正确：年化收益 15%–20%、2020-01-01 至 2024-12-31、Q1–Q3、换手率 3–5 倍/年
  - 错误：15%-20%、3 ~ 5 倍/年
  - 注意：`2024-03-31` 里的 `-` 是 ISO 日期格式的一部分，不是区间连接符，不要改
- **两端都要带单位或百分号**
  - 正确：67%–89%、132 kg–234 kg
  - 错误：67–89%、132–234 kg

### 3.7 专有名词大小写

按品牌官方写法：GitHub、iPhone、macOS、JavaScript、Microsoft、LeanCloud。
错误：github、GITHUB、Github、gitHub。

网页视觉需要的全大写 / 全小写，HTML 里仍按标准大小写，用 CSS `text-transform` 实现。

### 3.8 日期与时间

不限于金融或数据场景，任何中文文本里的日期时间都按此写：

- 中文日期：`2024 年 3 月 31 日`（月、日不补零）
- 纯数字日期：`2024-03-31`（补零，ISO 8601）；其中的 `-` 是格式的一部分，不是区间连接符
- 不用 `2024/3/31`；年份写满 4 位，不写 `24 年 3 月`
- 时间用**半角**冒号：`9:05`、`收盘 15:00`；不用全角 `9：05`
- 时间区间用 en dash：`9:30–11:30`

## 四、自检清单

改完或检查完，按顺序过一遍：

1. 中英文、中文与数字之间的空格（最高频错误；Markdown 标记、书名号内侧不加）
2. 全角标点是否用对（`，。；：！？、（）`）
3. 并列是否用顿号（英文并列词也用 `、`）
4. 中文正文里有没有 ASCII 直引号；引号风格是否全文一致
5. 数字与单位的空格是否全文一致
6. 区间连接符与两端单位（`15%–20%`，不是 `15-20%` 或 `15–20%`）
7. 标点堆叠、省略号 `……`、破折号 `——`
8. 标题末尾无点号
9. 专有名词大小写
10. 日期、时间格式（中文日期不补零、ISO 日期补零、时间半角冒号）
11. 受保护内容（代码、URL、公式、原文引用）是否被误改

机械项可以跑脚本先扫一遍。脚本在本 skill 目录的 `scripts/` 下，`$SKILL` 指本 skill 的绝对路径：

```bash
python3 "$SKILL/scripts/check_typography.py" 稿子.md
```

脚本只报确定性问题和候选问题，不自动改写。语境相关的判断（专有名词、house style、引用边界）仍要人过。
