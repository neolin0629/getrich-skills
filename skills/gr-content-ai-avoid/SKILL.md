# gr-content-ai-avoid：中文写作反 AI 指纹规范

你即将写中文内容。动笔前读完本文件，写作中执行，交付前自检。

**中文产出必须同时加载 `gr-chinese-typography-rules`。** 那份管排版格式，这份管表达方式，两者不重叠。

---

## 什么时候用 / 什么时候不用

| 情形 | 用不用 |
| --- | --- |
| 写任何中文原创内容（文章、笔记、口播稿、文案） | ✅ 用 |
| 改写、润色已有中文稿子 | ✅ 用 |
| 用户说「别写得像 AI」「去 AI 味」 | ✅ 用 |
| 用户要一份 AI 味检测报告 / 打分 | ❌ 用 `dbs-ai-check` |
| 写代码、写技术文档、写 commit message | ❌ 不用 |
| 写学术论文、法律文书、合规披露 | ⚠️ 只用 W / S / F 三层，C1、C2、C5 不适用 |
| 用户给了自己的写作样本 | ✅ 用，但**样本优先级高于本规范**（见下） |

**写作样本优先原则。** 用户如果提供了自己写过的东西，先分析它的句长、口头禅、标点习惯、段落开头方式，然后模仿那些习惯。样本和本规范冲突时，样本赢。像一个具体的人，就不像 AI；本规范只是没有样本时的默认值。

---

## 三条核心立场（不要跳过）

**1. 目标不是抹掉特征，是不要输出套路。** 「去 AI 味」这个说法本身有问题——把 AI 特征删干净，得到的是一篇没有味道的文章，同样不像人写的。方向是往「某个具体的人会怎么说」上靠。

**2. 写作的第一原则是有话要说。** 没有具体观点、没有真实经验、没有卡过壳的思考，39 条规则只是在把空洞包装得更像人。先想清楚要说什么。

**3. 完美本身就是不真实的信号。** AI 写作的问题不是写得差，是写得太光滑、太均匀。毛边、卡顿、跑题、没想通的地方，这些不是瑕疵。

## 工作流（三步，按顺序执行）

### 第一步：动笔前的强制自检

回答三个问题。**任何一个答不上来，先用 AskUserQuestion 问用户**，不要自行补全动机和角度：

1. 这篇最核心的一句话是什么？（写不出来说明没想清楚）
2. 哪一部分我自己也没完全想通？（那里要保留毛边）
3. 读者只能记住一件事的话，是什么？（让它最突出，其他让路）

还要确认**体裁**。体裁不明就问，不要默认按公众号长文写——各体裁的规则权重差别很大，见 `references/genre-profiles.md`。

用户在 prompt 里已经把这些讲清楚了就直接开写。

### 第二步：写作中执行规则

按下表的六层规则写。**完整规则、正反例、误伤阈值在 `references/rules.md`**——第一次为某个体裁写作时读一遍；已经熟悉规则时可只按下面的索引表执行，遇到拿不准的编号再回去查那一条。

中文 AI 高频词的完整词表在 `scripts/patterns.json`，分类说明和替换建议在 `references/cn-ai-words.md`。

**自检节奏：**

| 篇幅 | 节奏 |
| --- | --- |
| < 500 字（小红书短笔记、微博、朋友圈） | 不中途停，写完通查 |
| 500–1500 字（中等文案、口播稿） | 写完一半停一次，写完通查 |
| > 1500 字（公众号长文、研报、系列分析） | 每 500 字停一次，写完通查 |

### 第三步：交付前跑脚本

```bash
python3 scripts/check.py 稿子.md
python3 scripts/check.py 稿子.md --genre xhs-short   # 指定体裁，自动套用阈值与豁免
python3 scripts/check.py 稿子.md --json              # 机器可读输出
python3 scripts/check.py 稿子.md --fail-on high      # 有 🔴 命中时退出码 1
echo "文本内容" | python3 scripts/check.py -         # 从 stdin 读
```

脚本自动跳过代码块、frontmatter、行内代码、URL 和图片，只查正文。

**脚本能查 33 条**（词表命中 + 结构句式 + 密度指标）。**查不了这 6 条，必须人工过：**

| 查不了 | 自己怎么判断 |
| --- | --- |
| W4 同义词循环 | 同一段里换了几个词说同一件事？换回来 |
| C1 堵住所有反驳 | 你堵的这些反驳，哪个是真被人问过的？ |
| C2 知识全部输出 | 每个术语问自己「我理解它到什么程度」 |
| C3 让步模板反复 | 「当然 X 不是没有 Y，但 Z」用了几次？ |
| C6 命名仪式 | 造了几个「XX 效应」？留最精准的那个 |
| R3 经历服务于论点 | 有没有一个跟结论无关但你真记得的细节？ |

脚本报出来的每一处**都要人工复核再改**——脚本会误伤。`references/rules.md` 每条都写了误伤阈值。

## 规则索引（39 条）

严重度：🔴 强信号，几乎只有 AI 这么写 ｜ ⚠️ 中信号，AI 高频但人也会 ｜ 💡 弱信号，要结合体裁判断

### W · 词汇层（脚本可测）

| ID | 名称 | 严重度 | 一句话 |

| W1 | AI 高频词 | 🔴 | 「值得注意的是」「彰显」「赋能」「至关重要」，见词表 |
| W2 | 翻译腔 | ⚠️ | 「作为一名」「对…进行」「起到了…的作用」 |

## 交付前的通读顺序（按犯错概率排序）

1. **开头**是不是套路（P1、P2）——最容易犯
2. **结尾**是不是祝福或通用积极（P4）——最容易犯
3. 「本质上」「归根结底」「真正的问题在于」（C7）
4. AI 高频词与宣传腔（W1、C8、C9）
5. 连接词密度（W3）、翻译腔（W2）
6. 「不是 X 是 Y」次数（S3）、三段式（S1）
7. 排比与句长的均匀度（S1、S2）
8. 有没有一处承认不确定（R1）——**没有的话，这篇一定像 AI**
9. 术语和数据是不是都真的在用（C2）

## 体裁与领域调整

各体裁的规则权重、豁免项、误伤阈值见 **`references/genre-profiles.md`**。写作前先确定体裁再读对应档案。

已覆盖：公众号长文、小红书短笔记、小红书长图文、微博、知乎、短视频口播稿、朋友圈与人设日常、商业文案、金融量化专业内容、学术正式文体。

**金融 / 量化内容三条硬约束**（详见档案）：

- 堆数据不等于有观点。说清楚你从数据里看到了什么。
- 不确定性必须写出来。「这个策略在 XX 场景会失效」比「该策略跑赢基准」真实一百倍。R1 在金融内容里是最致命的 AI 指纹。
- 不写「市场本质上是 XX」。市场不是「本质上」的东西，是具体的买卖单、具体的资金流、具体的头寸。

## 写短文本时（评论、回复、私信、追问）

即使只有两三句，这几条照样守：

- 不用「你可能会觉得」开头（C4）
- 不用「不是 X 是 Y」结构（S3）
- 不用「本质上」「归根结底」升维（C7）
- 不用选择题结构（「是 A 还是 B？不，是 C」）——这是在替对方想答案
- 直接说观察到的现象，然后给一个具体判断或问一个开放问题

---

## 语气设定

- 像一个具体的人，不像会议主持人
- 不讨好读者，不承诺收获，不制造焦虑
- 敢写「我不知道」「我没想清楚」「这段我在犹豫」
- 能具体就不抽象：说「2024 年 3 月那次平仓亏了 8 万」，不说「那次经历让我深刻意识到」
- 重复可以、朴素可以、跑题一点也可以，但不要空洞

---

## 写完之后觉得还是有 AI 味

不要立刻改。先回答：**这篇你最想让读者记住的那一句话是什么？**

- 答得出来 → 围绕那句重组，其他让路
- 答不出来 → 选题还没想清楚，回构思阶段，不是改写阶段
