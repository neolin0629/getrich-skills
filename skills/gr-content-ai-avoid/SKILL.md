# gr-content-ai-avoid：中文表达去套路

目标是让内容具体、清楚，符合作者和读者的需要。流畅、正式、句长均匀都不构成写作问题；不要刻意制造卡顿、跑题或犹豫。

## 适用范围

- 中文文章、公众号、小红书、知乎、微博、口播稿、商业文案的创作与润色。
- 用户明确要求去 AI 味的短评论、回复或私信，采用轻量流程。
- 学术、法律、合规等正式稿件仅在用户要求风格修改时使用，保留必要术语、论证结构、限定条件和披露。
- 代码、技术文档、commit message、普通任务答复不默认使用。
- 用户只要诊断报告时保持只读；可用 `dbs-ai-check` 时由它处理，否则直接说明表达问题，不输出作者身份判断。

本 Skill 可独立使用。用户还要求中文排版检查，且 `gr-chinese-typography-rules` 可用时，再配合加载。

## 优先级与事实边界

**事实和原意 → 用户明确要求及风格样本 → 体裁需要 → 默认表达建议。** 以下约束适用于全部规则：

1. 改写不新增未经用户提供或核实的金额、日期、来源、因果关系、情绪和亲身经历，不改变观点力度或适用范围。发现原稿疑似错误时指出待核实点，不静默替换为另一断言。
2. 风格样本用于学习句长、用词、标点和叙述方式，不授权把样本里的经历或事实移入当前稿件。必要的直接引文、数据、术语和用户指定措辞原样保留。
3. 个人经历只能来自用户或明确材料；没有故事就用事实、解释或明确标为假设的例子。不得编造「我有个朋友」，也不得把它换成虚构的第一人称经历。
4. 只表达真实存在的不确定性。没有材料支持时，不补写「我没想清楚」、失败经历或无关生活细节。
5. 数字、姓名、匿名、叙事完整程度都不能单独证明真实或虚构。示例只示范表达，不能充当事实来源。
6. 改写前锁定必须保留的信息：数字及精度、来源、否定、条件、时间范围、因果与推断关系、程度与频率、完整枚举、作者判断和必要行动项。「只在」不能变成「主要在」，「可能较弱」不能变成「有效」，「显著」的统计含义不能换成情绪强调。多个限定各有作用时全部保留。

## 工作流程

### 1. 明确任务

从上下文提取核心意思、读者、体裁、语气和可用事实。用户给了样本，先提取表达习惯。只有缺失的信息会实质改变产出时才提问；不要要求额外提供故事、犹豫或隐私。

按 [体裁档案](references/genre-profiles.md) 选择对应设置。正式文体与平台偏好冲突时，优先保留表达的准确性和必要结构。

### 2. 写作或改写

先确定编辑权限，不需要为了选择模式额外追问：

- **诊断**：用户只要检查时，不改正文，说明候选、上下文及建议保留项。
- **最小改写（已有稿件去 AI 味的默认模式）**：先定位问题，不重新起草整篇。保留标题、段序、列表与未受影响句子；每一处修改应能对应具体问题。不能仅因不够口语、句长均匀、恰好三项或改写后更短就改。
- **创作 / 重写**：用户明确要求新稿、重构或改换文体时，才在授权范围内调整结构；事实和信息保留约束仍然有效。

创作时先完成连贯草稿；最小改写时仅处理定位片段，再按段落复核。不规定每 500 字中断，长稿可以在自然章节结束时复核。

39 条编辑规则按六层组织，具体条件、例外和示例见 [规则详表](references/rules.md)：

| 层次 | 编号 | 检查重点 |
| --- | --- | --- |
| 词汇 | W1–W5 | 空泛词、翻译腔、连接词密度、概念重复、无效填充 |
| 句法 | S1–S8 | 刻意凑项、节奏、重复翻转、空泛尾句、失当比喻 |
| 结构 | P1–P6 | 套路开头、空转、模板段、泛化收尾、不必要的清单 |
| 内容 | C1–C9 | 稻草人、无用术语、模糊归因、过度命名、宏大判断 |
| 真实感 | R1–R5 | 真实边界、数据精度、经历来源、身体感受与论证的关系 |
| 格式 | F1–F6 | 装饰密度、对话残留、推测填空、无关奉承 |

初次使用读规则详表；后续按命中编号或任务需要查阅。需要用词处理思路时读 [词库说明](references/cn-ai-words.md)，不必将词表当成禁词清单加载。

### 3. 检查与交付

完整稿件交付前运行脚本一次。`$SKILL` 代表本 Skill 的绝对路径，正文通过文件或 stdin 输入。不要把未转义的稿件内容直接拼入 shell 命令；无文件交付要求时使用 stdin 或临时文件。

```bash
python3 "$SKILL/scripts/check.py" 稿子.md --genre xhs-short
python3 "$SKILL/scripts/check.py" 稿子.md --json
python3 "$SKILL/scripts/check.py" - --genre wechat
python3 "$SKILL/scripts/check.py" 稿子.md --fail-on high
```

- `high` / 🔴：优先复核；`mid` / ⚠️：常规复核；`low` / 💡：语义候选。均不代表 AI 身份证据或必须修改。
- `--fail-on high` 仅由高优先项触发退出码 1；`--fail-on any` 包括低优先候选，适合收集待审项，不宜作为文章必须通过的门槛。默认 `never` 不因命中失败，输入错误返回 2。

脚本只定位候选，不自动改正文。需要解释 JSON 字段、统计口径、体裁配置或排查定位时，读取 [脚本说明](references/script.md)。

**复核顺序：** 先逐项对照必须保留的信息，检查是否漏项、偷换程度或把推断变成事实，再看开头结尾、重复结构、用词与格式。最小改写模式逐处检查差异：不能解释必要性的改动撤回。只修改确实损害表达的部分。发生实质修改后复查受影响项；合理命中可保留，不追求清零。完成一轮修改与复核、没有新问题时停止，不反复重写追逐指标。默认交付正文，不附自检报告。

两三句短回复只检查事实、语气、冗余和对话场景是否自然，可省略脚本。真实纠正可以用「不是……是……」，礼貌问候可以祝福，正常提问不必改成固定句式。

脚本不可运行时按相关规则人工复核；不要声称已经运行检查，也不要为此要求用户建立完整工具环境。

## 维护入口

- [scripts/patterns.json](scripts/patterns.json)：词表、正则、阈值、体裁配置和人工检查项。
- [scripts/check.py](scripts/check.py)：候选定位、指标与报告。
- [脚本说明](references/script.md)：JSON 字段、统计口径、体裁配置与去重规则；改变输出或执行契约时同步。
- 修改规则时同步核对规则详表、词库说明、体裁档案和回归样例，尤其是「应保留」的反向样例。
- [研究借鉴与限制](references/research-notes.md)：供维护规则时查阅，不是每次写作的必读上下文。
