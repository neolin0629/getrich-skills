# gr-content-review：内容评审

帮作者把这一篇改到能兑现自己的判断。只评内容，不代写。

## 适用范围

- 中文文章、小红书或公众号笔记、即刻短文、长文的草稿或定稿。
- 只评内容。标题字数、图注、链接、Markdown 渲染等格式问题交给渠道写作 Skill 或 `gr-chinese-typography-rules`；其他专项见「转交」。
- 默认只读，不修改稿件。调用方指定评审记录文件时，只在该文件末尾追加本轮结果。

## 输入

| 输入 | 必需 | 用途 |
| --- | --- | --- |
| 稿件 | 是 | 评审对象 |
| 写作方式 | 否 | 本人写作或 Agent 起草，决定修改强度；未说明且无法从上下文判断时按本人写作处理 |
| 任务单或选题 | 否 | 目标读者、核心判断、主要目标；缺失时从稿件推断，标为 Agent 假设 |
| 平台、账号规则 | 否 | 体裁、读者和禁止事项 |
| 作者偏好 | 否 | 本人确认的偏好优先于本 Skill 的默认做法 |
| 来源材料 | 否 | 核对事实、数字和引用 |

调用方给了路径就按路径读取，只读与本篇相关的部分。不扫描整个内容仓库。

## 优先级

**事实和原意 → 作者确认的偏好与账号规则 → 任务单目标 → 本 Skill 默认。**

区分四类信息，写进结果时分别标明：本人确认的偏好、Agent 假设、外部写法、事实证据。不把 Agent 假设写成作者偏好。

## 评审四问

1. **承诺**：标题和开头承诺了什么？正文是否兑现？指出缺失、偏题或结尾没有落地的段落。
   - 先遮住后文，只看标题和开头：目标读者有没有理由读下去？开头指平台默认展示的部分，如小红书折叠线内的前几行、公众号会被截成摘要的第一段；其他体裁看前两三句。开头留不住人时，后文写得再好也不能抵消。
   - 列出稿件提出的主张。多个主张并列、没有一个统领其余时，标为「核心被稀释」，建议保留哪一个，其余降为证据或案例。标题承诺的就是清单（如「5 个避坑点」）时，清单本身就是统领，不适用这条。
   - 标题或开头的承诺越强，条件和范围越要靠前交代。条件有但出现太晚，归在这一问；完全没有，归第 2 问「缺边界」；两处同一根因时合并成一项。
2. **证据**：数字、日期、引用和因果推理能否支撑结论？分成已核实、待核实、作者个人判断或预测三类。待核实的写明缺什么来源，不自行补数字或来源。强判断只讲成立的一面、没有交代在什么情况下不成立时，标为「缺边界」。
3. **立场与细节**：作者的判断、经历和关键措辞是否保留？有没有被稀释成没有立场的概括？外部作者的经历没有写成作者自己的经历。
   - 一句话放进另一篇同类稿子也成立，说明丢了只有作者才有的细节。经验类稿件，或稿件自称「从我的经验出发」时，至少要有一处只有亲历者才知道的信息；评论和分析类稿件只作建议。
   - 案例写成「某公司」「某用户」「我有个朋友」，又没有能核实的细节（时间、过程、具体数字或对话）时，按待核实处理，写「需要你补：……」。作者有意匿名时保留匿名，只补细节，不补身份。
4. **读者**：目标读者能否读懂（术语、跳步、前提缺失）？为什么会读下去、收藏或认同，与主要目标是否一致？
   - 用一句话说出读者能带走什么：一个判断、一个方法或一句能转述的话。说不出来，或目标读者读完会觉得「这个我知道」，标为「价值落点缺失」。没有同类内容对照时，「读者已知」标为 Agent 假设。

## 流程

1. 读输入，用一句话写出目标读者、核心判断和主要目标。从稿件推断的内容标为 Agent 假设。
2. 按四问逐项检查，记下候选问题。
3. **选题出口**：只在两种情况下使用，并且只陈述缺口，由作者决定怎么处理。
   - 核心判断在证据或逻辑上立不住：前后矛盾，或支撑它的证据全部缺失。Agent 不同意这个观点不算。
   - 作者手上没有能写的材料：需要的经历、数据或案例都不在稿件和来源里。

   这时不凑三个小修改，按输出模板的「选题出口」写法只报这一项。说清是缺材料（补什么）还是判断不成立（哪里矛盾、缺什么证据）。本人写作时不给替代的核心判断，最多列 2–3 个方向供作者选。读者兴趣、选题热度这类推断不触发选题出口。
4. 否则选出最多三个优先项。排序依据：影响结论可信度 > 承诺没有兑现 > 读者理解 > 吸引力。同一根因的问题合并成一项。
   - 上游问题（开头留不住人、核心被稀释）进入优先项时，修好它之后会改变或消失的下游问题，合并成一条放进「其他观察」。
   - 上游问题自己没进优先项时，不触发降级。
   - 事实、数字和引用问题不因上下游关系降级。
5. 每项写位置（引用原句或小节名）、问题、影响和最小修改。
6. 列出 1–3 处值得保留的表达，说明保留理由。
7. 诊断留在四问里。只把需要改写或专项处理的部分写进「转交」，每项一行。

## 最小修改

- **本人写作**：不重写段落。给修改方向和需要补充的信息；确需示例时最多一句，标「示例」。保留原有措辞、节奏和观点力度。
- **Agent 起草**：可以给替换句，范围不超过原段落。
- **不改立场**：强判断或预测的问题只在证据不足时，建议补条件、范围或标明为个人判断，不改结论方向。作者已要求保留的表达不提修改，只说明证据边界；记录取舍后不再重复提出。
- **不编造**：缺少经历、数据或来源时写「需要你补：……」，不替作者填。

## 不做

- 不打总分，不预测爆款概率，不用「还不错」之类的笼统评价。
- 优先项不超过三个。次要问题放在「其他观察」，最多三条，每条一句。
- 不做去 AI 味、排版和平台风险检查；作者偏好要求跳过某项检查时，转交里也不再建议。

## 转交

只列本篇确实出现、需要改写或专项处理的问题；四问范围内的诊断不转交。对应 Skill 不可用时，说明并给出人工检查点。

| 问题 | 建议 |
| --- | --- |
| 格式、平台字数与渲染 | 渠道写作 Skill |
| 中文排版 | `gr-chinese-typography-rules` |
| 套话、机械重复 | `gr-content-ai-avoid` |
| 标题、封面标题、开头重写 | `dbs-title-cover-intro` |
| 逐句共鸣删改 | `dbs-resonate` |
| 发布风险 | `dbs-content-risk-check` |
| 受众、流量与商业价值 | `dbs-content-value` |
| 传播机制 | `dbs-spread` |

## 输出

```markdown
## 内容评审

日期：{YYYY-MM-DD}。稿件：{路径或标题}。写作方式：{本人写作／Agent 起草}。依据：{任务单、偏好、来源；缺失项写明}

| 项目 | 内容 |
| --- | --- |
| 目标读者 | {一个具体人群和当下问题}（{来源或 Agent 假设}） |
| 核心判断 | {一句话} |
| 主要目标 | {阅读／收藏／认同} |

### 优先项

#### 1. {一句话问题}

- 位置：「{原句}」或 {小节}
- 问题：{具体说明，引用证据；证据类问题写明已核实／待核实／个人判断或预测；判断依据标为事实证据、本人确认的偏好、外部写法或 Agent 假设}
- 影响：{对可信度、兑现或读者的影响}
- 最小修改：{方向与需要补的信息}

### 值得保留

- 「{原句}」：{理由}

### 其他观察

- {可选，最多三条}

### 转交

- {可选，问题 → Skill}
```

走选题出口时：优先项只写一项，位置写「全篇」；「最小修改」换成「需要你决定」，写明缺材料（补什么）或判断不成立（哪里矛盾、缺什么证据），本人写作时最多附 2–3 个方向；「值得保留」照常写，「其他观察」和「转交」省略。

写入评审记录文件时，末尾加「本人取舍」小节并留空，等作者填写取舍和原因。
