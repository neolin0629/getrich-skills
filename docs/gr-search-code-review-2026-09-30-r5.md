## 1. [P2] 按文本定位删除菜单，误删代码块（r4-1）

**复现**：代码块里先有一份与真实菜单相同的三行链接，真实菜单出现在代码块之后。渲染后：
- 代码块只剩开头和结尾两行 ```` ```text ```` / ```` ``` ````，中间三行被删；
- 真实菜单反而原样保留。

**根因**：`_drop_units` 只拿到待删单元的文字，从 `cursor` 起找"第一次出现的同文行"，完全不知道分段阶段的边界。同一问题不限于代码块：只要菜单里的某一行在更早的普通段落中也出现过，删掉的就会是那个段落里的行。

**修复方案**：
- 让 `_passage_units` 能同时给出每个单元对应的原始行区间 `(start, end)`，例如加一个返回 `(unit, start, end)` 的内部版本，`_passage_units` 保持现有返回值；
- `_fit_body` 的回退路径按区间删除，不再按文本查找；
- 长段落按句切开的单元共用同一个区间，这类单元不删，与 `_drop_units` 现在"对不上就不删"的保守原则一致。

**回归用例**（全链路）：
- 代码块先出现、真实菜单在后：代码逐行保留，真实菜单被剔除；
- 普通段落中含同文行、真实菜单在后：段落完整，菜单被剔除。

## 2. [P2] 弹窗 fragment 规则误合并合法路由（r4-2）

**复现**：`#/login`、`#/portal/reports`、`#/account/profile` 都归一成 `//app.example/`。作为对照，`#/search?q=x` 却没有折叠，同一张表内部行为也不一致。

**根因**：`_UI_FRAGMENT` 按名字认定"弹窗"，但 `login`、`account`、`portal` 在很多 SPA 里就是内容路由。唯一的证据只是 Ghost 的 `#/portal/`。

**修复方案：删除 `_UI_FRAGMENT`，只保留去掉 `:~:` 文本指令这一步。** Ghost 的情况不需要专门规则：`#/portal/` 与不带 fragment 的 URL 返回的是同一篇文章，标题和正文完全相同，已有的严格正文去重（`_equivalent_key`）会把它们合并。这样既去掉了误合并，也不丢 1.2.5 想修的那个样例。

**回归用例**：
- 首页与 `#/login`、`#/portal/reports`、`#/account/profile` 的正文不同时，各自保留，RRF 各为 `1/61`；
- `#/portal/` 与原 URL 标题、正文相同时，经 `merge()` 合并为一条，另一个 URL 进入 `also_urls`。

## 3. [P2] 资料链接仍被当成导航（r4-3）

**复现**：
- 普通标题 `# …` 加两条资料：链接保留；
- 链接标题 `[# …](url)` 加两条资料：两条都丢失，因为标题自己贡献了第三个链接；
- 普通标题加三条资料：三条都丢失。

**根因**：菜单判定只看链接数量。把阈值从 2 调到 3，只是把失败点从"两条资料"挪到了"三条资料"。

**修复方案**：
- **标题不参与菜单计数，并且打断连续段。** `_heading_level` 大于 0 的单元既不计入 `links`，也结束当前 run。
- **门户菜单和资料列表的区别在锚文本，不在数量。** 菜单锚文本很短，而且模式重复（"北京天气 / 上海天气 / 广州天气""首页 / 新闻"）；资料链接是描述性标题（"Python 3.14 官方文档"）。建议 run 只有同时满足以下两条时才算菜单：
  - 链接数 ≥ 3，或 ≥ 2 且夹着纯文本导航词（保持现状）；
  - 锚文本长度的中位数 ≤ 8 个字符（中文按字、英文按词计 2），或者 run 中含有纯文本导航词。

  请先用现有的真实形态用例和 9/29 的 tianqi.com、eastday 两份 raw 校准这个阈值，不要只看新写的样例。

**回归用例**：
- 普通标题、链接标题 × 2 条、3 条、5 条资料链接，全部保留；
- `test_weather_navigation_does_not_displace_forecast`、`test_navigation_with_titles_and_separate_list_items_does_not_hide_forecast`、`test_real_portal_menus_are_still_navigation` 继续通过；
- 9/29 两份 raw 回放后，tianqi.com 仍不出现菜单行。

## 4. [P3] 年份判定：带空格的单位（r4-4）与紧贴中文的年份（本期新增）

**复现**（今天为 2026-09-30）：

| 查询 | 1.2.4 | 1.2.5 | 期望 |
| --- | --- | --- | --- |
| 茅台股价 2000元 | 历史 | 实时 ✅ | 实时 |
| 茅台股价 2000 元 | 历史 | **历史** | 实时 |
| stock price below 2000 USD | 历史 | **历史** | 实时 |
| 茅台股价跌破 1999 元 | 历史 | **历史** | 实时 |
| 北京天气2025 | 历史 ✅ | **实时** | 历史 |
| 上海天气2024 | 历史 ✅ | **实时** | 历史 |
| 北京天气 2025 | 历史 ✅ | 历史 ✅ | 历史 |

1.2.5 只看数字两侧是否为空白，这个特征与"是价格还是年份"无关：
- 带空格的单位被当成独立数字，于是算年份；
- 紧贴中文的年份被当成非独立数字，于是不算年份。

**修复方案：按主题决定裸数字的默认解释，再用单位和动词覆盖。**
- 数字后面（允许空白）跟着货币或点位单位（元、块、美元、港元、点、USD、RMB、HKD、pts、%），或者前面有价格动词（跌破、突破、站上、收于、报、涨至、跌至、below、above、under、over、at、$、¥），一律视为价格；
- 数字后面跟"年"，一律视为年份；
- 其余裸数字：主题为天气时默认是年份，主题为股价、汇率、比分时默认是价格或数值。

这样"北京天气2025"恢复为历史查询，"茅台股价2050"保持实时，r4 的三个反例也都能判对。

**回归用例**：上表 7 行全部加入参数化用例，外加"北京2025年天气""weather Beijing 2019"两个已有用例继续通过。
