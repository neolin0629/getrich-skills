## [P3] 关键词列表仍有两个方向的缺口

两处都在 `_REFERENCE_HEADING`，复现方式与前几期相同，都走全链路 compact/8000。

**漏掉的资料章节（该保留，却被删）**：下面是 PEP 8 / Black / Ruff 这类短名称资料链接。

| 章节标题 | 1.2.9 |
| --- | --- |
| `## 参见` | 链接被删 |
| `## 扩展阅读` | 链接被删 |

"参见"是中文维基百科里 See also 对应的标准章节名。同一类还有"拓展阅读""相关条目"。

**宽泛的英文单词（该删，却被保留）**：下面是 Blog / Docs / Help / Community 这类站点页脚链接。

| 章节标题 | 1.2.9 |
| --- | --- |
| `## Resources` | 页脚菜单保留 |
| `## Documentation` | 页脚菜单保留 |

这与 r8 修掉的中文"资料 / 参考"是同一类问题，只是在英文侧：`resources?`、`documentation` 仍是单独的词，而这正是英文 SaaS 站点页脚最常见的栏目名。这个问题从 1.2.6 起就存在。

**若要修**：
- 中文补上"参见、扩展阅读、拓展阅读、相关条目"；
- 英文把 `resources?` 和 `documentation` 从单词改成短语，例如 `additional resources`、`learning resources`、`further documentation`；或者当标题只有这一个词时不开启保护。

## 为什么建议到此为止

- 从 r5 到 r9，这条"资料章节"规则已经改了 5 轮。每一轮修掉一批关键词，都会在另一侧露出新的缺口。这是用关键词列表去区分"菜单"和"引用"的固有局限，不是某一版实现写得不好。
- 在 415 篇真实正文里，这套资料保护**从未触发过**。导航剔除的结果自 1.2.6 起一直是 155 个单元，每一轮都没变。
- 剩下的缺口在真实数据上都没有出现：一类只是多展示几行菜单；另一类会丢掉几条短名称资料链接，但完整正文仍在落盘 JSON 里，可以找回。

如果以后要从根本上改进，更可靠的信号是结构和查询相关性，而不是标题词：
- 锚文本是否命中查询词；
- 链接是否指向与当前页面不同的站点（菜单大多是站内链接，参考资料多是站外链接）；
- 同一组链接是否在页首和页尾重复出现。

这类改动应该另开一个版本，用新的联网样本评估，不必塞进这一轮收尾。

## 其他核对（未发现问题）

- **网址剥离**：只作用于判定用的标题文字，展示原文和落盘内容不变。`<?https?://[^\s<>]+>?` 对大小写不敏感，网址后面隔着空格的"参考资料"仍能识别。例外是网址后面紧贴中文、没有空格（如 `https://x.example/a参考资料`）：中文会被当成网址的一部分一起去掉。这种写法极少，不定级。
- **测试文件**：`test_r8_regressions.py` 在修复前的 1.2.8 上有 45 项失败，修复后全部通过，能真实反映这两个问题。
