## 1. [P3] 资料关键词命中站点导航区块

**复现**：一篇新闻正文，章节标题下是 4 个站点链接，查询为"美联储 利率"，单条豆包正文，全链路 compact/8000：

| 章节标题 | 链接 | 1.2.7 |
| --- | --- | --- |
| `## Quick Links` | Home / About / Contact / Careers | 保留 |
| `## Related` | Markets / Tech / Sports / Opinion | 保留 |
| `## 阅读排行` | 体育 / 娱乐 / 财经 / 科技 | 保留 |
| `## 热门推荐` | 同上 | 剔除 ✅ |

在 1.2.6 里，前三种都会被剔除。

真实正文里已经出现过同类标题：`## Related Posts`、`## Related articles`、`### Related Articles`、`### Featured Links`、`## StreetStats 101 | Related Topics`、`[## Related ETFs](…)`。这批数据里它们下面恰好是长标题链接，本来就不算菜单，所以没有造成实际回归。一旦换成短分类名，就会被保留下来。

**根因**：`related`、`links`、`阅读`是站点"推荐 / 页脚 / 排行"区块的高频词，和"延伸阅读、See also"这类真正的资料章节共用同一批关键词。

**修复方案**：
- 改为短语匹配：`related reading`、`related resources`、`useful links`、`external links`、`相关阅读`、`延伸阅读`、`推荐阅读`；
- 同时排除推荐和排行类的修饰词：`posts`、`articles`、`stories`、`topics`、`quick`、`featured`、`排行`、`热门`；
- 或者要求关键词构成标题的主体。例如标题去掉标记后不超过 20 个字符，并以关键词开头或结尾。

## 2. [P3] 关键词匹配整个单元，一级标题保护全文

**复现**：

- `[# 北京天气](https://w.example/resources/bj)` 后面紧跟三个城市链接：因为 URL 里有 `resources`，这三个链接都不再判为导航。
- 文章标题 `# 2026 年度阅读报告`，下面先是三个站点链接，之后是 `## 正文`，再之后又是三个站点链接：两个菜单都不再剔除。`## 正文` 的级别低于一级标题，不会结束保护。

**根因**：
- `_REFERENCE_HEADING.search(unit)` 在整个标题单元上匹配，包括链接标题里的 URL 和 title 属性；
- 保护范围一直延续到下一个同级或更高级的标题。一级标题通常是文章标题，一旦命中，保护就覆盖整篇。

英文标题里的 `\brelated\b` 在 `AI-related`、`Fed-related` 中也能匹配，因为连字符构成单词边界，所以这类文章标题并不少见。

**修复方案**：
- 只在去掉 `#` 标记、链接 URL 和 title 属性后的标题文字上匹配；
- 一级标题不开启保护，或者只保护到下一个任意级别的标题为止；
- 回归用例覆盖：URL 含关键词的链接标题、标题含 `AI-related` 的文章、一级标题含"阅读"且后面有真实菜单。
