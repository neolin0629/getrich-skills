## 仍未修复：followup 的两个 P2

两个反例均按 followup 原文构造，通过 `render.render()` 全链路、compact/8000 执行：

| 反例 | 期望保留 | 1.2.4 实测 |
| --- | --- | --- |
| P2-1：标题下两条相关资料链接 + 大段背景 | 两个 docs.python.org 链接 | 两个都丢失，输出 2241 字符，主要是背景文字 |
| P2-2：`[# 北京天气](url)` 与数据用单换行相连 | 24 ℃、湿度 77% | 都丢失，输出 2215 字符 |

补充一点根因，供修复参考：

- **P2-1** 来自 `_navigation_units` 的连续链接判定：连续 2 个短链接单元就足以标成导航，与链接文字是否命中查询无关。建议把门槛提高到至少 3–4 个链接，或者链接文字命中查询词时不算导航。
- **P2-2** 来自 `_heading_level` 的链接标题分支：只看单元开头，就把整个单元当成标题。更干净的做法是在 `_passage_units` 分段时，把链接标题单独切成一个单元。

## 本轮新发现（均为 P3）

### P3-1 查询里的价格数字被当成历史年份

位置：`fusion.py` 中 `_query_has_past_date` 的最后一条规则。

任何以 19 或 20 开头、早于今年的 4 位数都算"历史年份"：

| 查询 | 是否识别为日级时效 |
| --- | --- |
| 茅台股价 2000元 | False |
| 茅台股价跌破1999 | False |
| 黄金价格 2010 | False |

股价、金价、点位经常是这个量级的数字。

**建议**：只有后面紧跟"年"，或者是独立 token 且不带"元/点/美元"等单位时，才当作年份。

### P3-2 保留 `/` 开头的 fragment 与真实数据冲突

位置：`fusion.py` 中 `canonical_url` 的 fragment 规则。

本机 23 次落盘里，唯一带 fragment 的 URL 是 Ghost 博客的会员弹窗：`polymarketintel.com/...-2026-conflict/#/portal/`。它不是 SPA 路由，却按 `#/` 规则被保留，于是同一篇文章带和不带这个后缀会分成两条，这正是去重本来要避免的情况。

同理，浏览器的文本片段 `#:~:text=…` 含有 `=`，也会被保留。这次数据里没出现，但属于同一类问题。

**建议**：
- 排除 `#:~:` 开头的 fragment；
- 对 `#/portal`、`#/login` 这类已知的弹窗路由做例外；
- 或者改成只在 fragment 看起来像多段路由时才保留，例如 `#/docs/install`。

### P3-3 `redact` 去掉了最短长度保护

位置：`sources.py` 中的 `redact`。

原来有 `len(secret) >= 8` 的保护，现在对任意长度的密钥都做替换。配置里如果留了一个短的占位值（比如 `test`），所有错误信息里的 `test` 都会被替换：

- 原文：`HTTP 400 latest test result: contest`
- 替换后：`HTTP 400 la[已脱敏的密钥] [已脱敏的密钥] result: con[已脱敏的密钥]`

真实密钥有 32 或 40 位，不受影响；但占位值恰恰最容易出现在排查阶段，那时错误信息被搅乱，会误导排查。

**建议**：完整密钥保持无条件替换，长度不足 8 时只做整词替换；或者直接在配置加载时把过短的密钥判为无效。

### P3-4 数值继承带进大量无上下文的数值

位置：`render.py` 中新增的 `_MEASURED_VALUE` 继承。

只要单元里有带 ℃、%、hPa 或"级"的数字，就会继承章节标题的命中。回放中，tianqi.com 这一条选出了约 40 行 `* 1级`、`* 2级` 列表项。这些是逐小时风力，但对应的时刻不在同一个单元里，读者无法使用。

同一机制在非天气页面上也会生效：标题命中查询时，该章节下任何带百分比的段落（比如"折扣 50%"）都会成为候选。

**建议**：
- 继承只给"数值 + 标签"同在一个单元的块，例如"湿度 77%"；
- 或者对连续的纯数值短单元整体限额。

### P3-5 前缀回退会把表格拆成隔行

位置：`render.py` 中 `_fit_body` 新增的菜单剔除回退。

剔除菜单后，剩下的单元用 `"\n\n"` 重新拼接。但表格在分段时是按行切开的，重新拼接后每行之间多了空行（`|日期|气温|`、空行、`|---|---|`、空行……），Markdown 表格结构被破坏。

**建议**：直接在原始行上删除菜单所在的行区间，不要重新拼接单元。

## 观察（不算缺陷）

- **正文里的过期快照变得更显眼了。** eastday 那条的发布时间是 9/20，正文开头就是"2026年09月20日 … 24 ℃ 多云 22-30℃"。9/29 查询时，它排在第 12 名（9 天内的发布日期在日级时效下还能 +1%）。菜单剔除之后，这段旧数据从被导航淹没，变成了清楚可读的"当前天气"样式。日期写在正文里，读者可以辨认，但排序日期没有利用正文开头的日期。可以考虑：对行情类结果，把正文前 200 字符里的单一完整日期也作为排序日期的候选。
- **导航词表 `_NAV_LABELS` 基本是照着这两个天气站写的**（天气网、东方天气、台风专题、老黄历……）。这能修好回放样本，但对新闻门户和文档站没有泛化能力。长期看，应以结构特征（链接密度、行长、重复度）为主，词表只作补充。
- **README 1.2.4 记录中的噪声标注由实施者本人完成，而且不是盲评。** 文中已如实说明，这里提醒一下：不要把它和后续轮次的配对结果直接比较。
