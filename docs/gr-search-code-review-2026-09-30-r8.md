## 1. [P3] 中文资料关键词仍按子串匹配

**复现**：股票类正文，查询为"茅台股价"，章节标题下是"行情 / 资讯 / 财务 / 股东"四个站点标签链接，全链路 compact/8000：

| 章节标题 | 标签菜单 |
| --- | --- |
| `## 公司资料` | 保留 |
| `## 个人资料` | 保留 |
| `## 投资参考` | 保留 |
| `## 今日参考价` | 保留 |

**根因**：r7 之后，英文关键词已经收窄成完整短语并加了排除词，但中文的"资料""参考""文献"仍是单独的子串。财经站点常见"公司资料""投资参考"这类栏目名，下面往往就是站点标签页。

这个问题从 1.2.6 就存在，性质和 r7 第 1 条相同，只是出现在中文侧，所以记为 P3。真实语料里没有出现这类标题。

**修复方案**，与英文侧保持一致：
- 中文改为短语匹配：参考资料、参考文献、相关资料、学习资料、官方资料、官方文档、相关阅读、延伸阅读……
- 或者给"资料""参考"加排除词：公司、个人、基本、投资、参考价、下载。

**回归用例**：上表 4 种标题下的菜单被剔除，`## 参考资料`、`## 参考文献`、`# Python 3.14 官方资料` 仍保留资料链接。

## 次要观察：标题里的尖括号链接和裸 URL 仍会泄露关键词

`_heading_text` 已经能正确去掉标准链接的目标地址（包括嵌套括号和 title 属性），但以下两种写法仍然保留原样 URL：

| 标题 | 提取出的文字 | 是否开启保护 |
| --- | --- | --- |
| `## 北京天气 <https://w.example/resources/bj>` | 原样保留 URL | 是 |
| `## 北京天气 https://w.example/resources/bj` | 原样保留 URL | 是 |

标题里直接放 URL 的情况很少，不单独定级。修中文关键词时可以顺手去掉 `<…>` 自动链接和 `https?://\S+`。

## 其他核对（未发现问题）

- **`_heading_text` 的链接解析**：能处理 URL 中的平衡括号、反斜杠转义、单引号或双引号 title 属性。括号不配平时放弃剥离，不会截断正文。引用式链接 `[文字][ref]` 保留方括号原文，不会引入 URL。
- **保护范围**：一级资料标题会被下一个任意级别的标题结束保护；二级及更低的资料章节保护到同级或更高级标题为止，下级小节继续受保护。重置之后，当前这个标题仍会被重新判断是否开启保护，顺序正确。
- **排除词**：只作用于提取后的标题文字，`Related Posts` 这类标题不会因为 URL 或 title 属性而绕过排除。
- **`fusion.py`**：本轮未改动，r6 的年份判定保持不变。
